# M0 source capability probe

## Running and inspecting the local probe

Run `./scripts/test-m0.sh` from the repository root. It builds a fixture Wasm and a production Wasm, verifies the DFINITY release artifact hashes, runs the unit and PocketIC tests, and checks the generated Candid with `candid-extractor` 0.1.6 and `didc`. The current suite also includes M1 tests and the original-M0-to-current upgrade. PocketIC can use a supplied 14.0.0 binary via `POCKET_IC_BIN` or download its version-matched server. All execution and cycle accounting takes place in a local instance.

The integration tests export each receipt as Candid and each successful raw reply as its own binary under `.local/receipts/`. Receipts track the exact argument and reply hash, source and caller principals, caller subnet, decoder revision, sent/received times, cycle snapshots, observation or rejection, and retry attempt. The probe API exports reply bytes in 128 KiB pages. The status endpoint shows the observed Registry head, remaining work, total raw reply bytes retained, stable pages and canister balance.

## Limits and measurement interpretation

One controller may schedule a probe at a time. A job runs one bounded-wait call at a time with a 30-second timeout, at most two attempts for retryable calls, and a 64-receipt cap. Across the installation, the probe accepts at most 12 jobs and reserves room for a full reply within a 128 MiB raw evidence ceiling. A 50-billion-cycle balance floor stops collection. Governance listing starts at 10 rows and reduces to 5, 2 and 1 after the replica's observed oversized-reply error. Registry replay samples two whole-version pages for a nonempty Registry. Direct record reads use a pinned spot join. Chunk candidates are accepted from Registry wire replies and verified in order, with four chunks and a 6 MiB assembled-record limit. Exported source evidence is available through a replicated controller read. Report certification and retention policy belong to later milestones.

Recorded per-call cycles are the before-send to callback balance difference. The start-to-completion balance delta also includes probe scheduling, decoding and durable writes, plus any polling or upgrades explicitly listed. Stable memory counts are allocated 64 KiB pages. Memory-manager bucket allocation can dominate the allocated count for small stores. PocketIC intervals use its clock and do not estimate live network latency.

Official limits list 2 MiB for both cross-subnet message payload and replicated response size. Governance individual retrieval has no paginated payload method. An otherwise valid response that exceeds the protocol limit is an explicit source gap. Registry pages have an upstream byte and version limit. Remote management methods operate separately by subnet, so one rejection can leave other evidence usable. [IC resource limits](https://docs.internetcomputer.org/references/resource-limits/#message-limits)

## Authorized live verification

The [current operations runbook](OPERATIONS.md#live-verification-plan) uses the budgeted probe entry point. The examples below record the historical M0 commands.

Use a funded ordinary application canister ID, an already authorized deployment identity, confirmation of the install or upgrade mode, and an explicit budget. Use an existing canister only if its owner has assigned it to this probe and confirmed the intended mode. Select a public membership proposal ID and a known conventional replica subnet distinct from the probe’s own subnet. The Registry join defaults to the first subnet in the captured roster. Select an explicit subnet if needed.

After authorization, verify the existing controller and module information, then install on the designated empty canister. These commands use the production build whose initialization accepts `null` for canonical sources.

```bash
cargo build --locked --release --target wasm32-unknown-unknown -p nexus-reviewer
sha256sum target/wasm32-unknown-unknown/release/nexus_reviewer.wasm
dfx canister info --network ic --identity "$NEXUS_DEPLOYER" "$NEXUS_CANISTER"
dfx canister install --network ic --identity "$NEXUS_DEPLOYER" \
  --mode install --argument '(null)' \
  --wasm target/wasm32-unknown-unknown/release/nexus_reviewer.wasm "$NEXUS_CANISTER"

dfx canister call --network ic --identity "$NEXUS_DEPLOYER" --update \
  --candid canisters/reviewer/reviewer.did "$NEXUS_CANISTER" start_probe \
  "(record { proposal_id = opt ($NEXUS_PROPOSAL : nat64); registry_subnet = null; remote_subnet = opt principal \"$NEXUS_REMOTE_SUBNET\"; metrics_start_nanos = 0 : nat64 })"
```

Use the returned job ID with `probe_status '(1 : nat64)'`, `probe_receipt '(1 : nat64, 0 : nat32)'` and `probe_reply '(1 : nat64, 0 : nat32, 0 : nat32)'` on the same `dfx canister call` prefix. For each receipt, follow the reply’s next offset and verify SHA-256 over the concatenated reply bytes. Capture the source module hashes before and after the run using public canister info. Preserve actual receipt bytes, replica observations, ingress times, cycle deltas, probe artifact hash and any error classification in the release record.

Closely compare the abbreviated listing with its individual follow-up and capture a live large-payload case if present. Compare the two Registry cursors with each page’s observed head and record an older pinned spot read, a missing key, and any trusted chunk example. Observe management history on both subnets, including sample counts and times. When there is a sample the probe repeats the latest timestamp inclusively and records whether the overlapping sample matches. This is consensus blockmaking evidence with subnet-specific retention. It cannot establish wall-clock uptime.

## Capabilities observed

| Gate | Local result | Live result |
|---|---|---|
| Governance `list_proposals`, exclusive cursor and both omission flags | PASS. A production-built application canister called the released Governance Wasm with seeded test state. Both listing flag settings omitted a 1,209-byte executable payload. The exclusive cursor returned no additional rows. | Unresolved |
| Governance `get_proposal_info` and missing ID | PASS. Released Wasm returned the full 1,209-byte action and a separate request returned `None`. Unit tests cover functions 31, 2 and 13, unknown variants and function 18. | Unresolved |
| Registry raw protobuf `get_latest_version` and `get_changes_since` | PASS against the released Wasm on an empty Registry. A separate wire fixture delivered versions 1–3 and 4–5 with observed head 5, including a deletion and a highest mutation from an ignored family. | Unresolved |
| Registry `get_value`, pinned historical read and membership/node/operator/DC decode | PASS against the wire fixture. The join is pinned to version 5, whose subnet-list mutation is version 3. The earlier read pins version 2 and returns the version-1 mutation. A missing key returns an unavailable result. | Unresolved |
| Registry Candid `get_chunk` and ordered reconstruction | PASS against the wire fixture. Received two chunks and verified both hashes, joined the original encoded DC bytes and decoded the record. Unit tests reject missing content, source error and a mismatched hash. | Unresolved |
| Management `subnet_info` | PASS using PocketIC’s management implementation from the application subnet, for both local and remote subnet IDs. Each returned the test environment’s configured replica version `0.9.0` and Registry version 2. | Unresolved |
| Management `node_metrics_history` | PASS for same- and cross-subnet routing and empty replies via PocketIC’s native management implementation. An invalid target rejected with code 3 and the valid local target still succeeded. Sparse, inclusive and malformed response shapes are tested with fixture bytes. | Unresolved for populated history, actual retention and live response limits |
| Replicated query constraints | PASS in PocketIC. A query certificate was present for a direct read and absent in the replicated inter-canister call. A 2,097,166-byte client query reply succeeded and its replicated cross-subnet equivalent rejected at the 2,097,152-byte limit. | Unresolved on the live route |
| Durable queue and evidence | PASS for a Wasm upgrade after receipts were persisted and queued steps remained. The timer resumed and exported replies kept their original hashes. In-flight callback interruption and fleet-scale recovery remain future tests. | Unresolved |

Each profile has its own evidence directory below `.local/receipts/`. The `pinned-nns-wasm` profile runs the upstream binaries with locally seeded Governance proposals and an empty Registry. The fixture environment omits the ICP Ledger, so Governance's unrelated periodic ledger read can log a missing canister. The `synthetic-wire` profile uses fixture canister responses and actual PocketIC management routing. The evidence paths are local and Git-ignored.

The tested production probe Wasm was 1,693,624 bytes. The small test runs allocated 513 stable pages (about 32 MiB), mostly fixed bucket allocation from the four stable structures. The raw byte totals above are logical reply storage. The probe exports gross cycle snapshots. Some observations showed no debit in the individual callback window, so use whole-run deltas for budgeting and treat per-call values as approximate. Small-response calls in these samples were in the low tens of millions of cycles. Response size materially affected the large-page call. These samples can size a local experiment. A usable live cost estimate for full Registry bootstrap and daily collection needs real page, fleet and history sizes.

## Evidence gaps carried forward

- A public module hash match establishes the artifact identity of Governance and Registry. The live call path from a funded application canister is the remaining feasibility gate.
- The native metrics path returned successful empty histories. Observe populated histories and repeat the inclusive boundary on live samples before validating collection cost or retention. The metrics describe consensus blockmaking opportunities. Exact wall-clock uptime and unassigned-node readiness are unavailable from those observations.
- Historical proposal lookup may be unavailable after retention limits. Registry mutations and Governance lifecycle observations do not supply a shared causal ID. Historically inferred baselines require independent evidence and a label.
- A live chunked response and a nonempty live two-page Registry replay are still needed to size the mainnet workload.
