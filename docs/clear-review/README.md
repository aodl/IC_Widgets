# Factual Membership review

Enter a Membership proposal ID and select **Review**. The overview shows the selected membership state, individual nodes at registered locations and before-to-proposed group counts. Select a group to inspect its nodes, shares and descriptive coefficient. **Sources & details** shows evidence coverage, source receipts and the exact calculation input. **Review options** accepts a second proposal ID. Performance is available separately.

The ordinary review applies no Target Topology assumptions. The pinned `nns_subnet_id` Registry record establishes the NNS role. An unavailable role is reported as evidence coverage. Loading completion and unchecked assignments are separate. [Source manifest](SOURCES.md)

The recorded walkthrough uses **144954** and Registry **66,013**. Its banner identifies the synthetic NNS-role supplement. The original Governance capture and the replay delivery have separate timestamps. [Local and HTTPS replay setup](../review-fixtures/README.md)

Each page uses an automatically generated identity and owns one expiring review context. Contextual detail pages admit keys from its observed membership graph and bind their typed replies to the comparison. The canister caps the graph at 256 keys per record kind with two attempts per key. The browser starts with the selected subnet and reuses evidence across up to six order and step comparisons for that subnet. Other subnets stay outside enrichment until selected and share the same overall key budget. The final Governance update checks lifecycle and payload fields after comparison. A failed verification leaves a provisional view. [Public request limits](../ARCHITECTURE.md#evidence-and-request-limits)

## Uncoached walkthrough

Give the owner the fixture page and the scenario name. Ask them to identify whether the review has finished, the outgoing and incoming nodes, the subnet size, which groups changed, and which conclusions the evidence supports. Ask them to find the members behind a concentration row and return to the overview. Run the task with a held location reply and a completed review. Record their reasoning and navigation. Browser automation verifies interaction behaviour and request receipts. Participant observations require the owner walkthrough.
