# Clear review and Target Topology

Enter a membership proposal ID and select **Review**. The reference motion is selected automatically. **Review options** provides a reference override and a second proposal ID. The map remains available during enrichment. **Sources & details** opens the shared inspector with provenance, registered members and the exact computation input. Select a measure to inspect each group's assessment and highlight the contributing nodes. Performance is available separately from the header.

The default reference is **#143190**. Governance supplies its actual text and rule values on demand. The implementation supports the NNS role established by the pinned Registry. Other policy roles remain unsupported because their authoritative bindings are unavailable. The recorded walkthrough starts by entering only **144954**. Latest-policy applicability is unverified. The fixture combines the recorded Registry 66,013 and Governance membership replies, the recorded #143190 Governance reply, and a synthetic pinned `nns_subnet_id` record pointing to the fixture's NNS target. The source reply hash for #143190 is `9f2e78492a227992e5b413eca5f38e6a7eaa31f109ab164d400ea3f954d28053`. [Local replica setup](../map-first-review/README.md#reproduce-locally)

Each page uses an automatically generated identity and owns one expiring review context. Contextual detail pages admit keys from its observed membership graph and bind their typed replies to the comparison. The canister caps the graph at 256 keys per record kind with two attempts per key. The browser starts with the selected subnet and reuses evidence across up to six order and step comparisons for that subnet. Other subnets stay outside enrichment until selected and share the same overall key budget. The final Governance update checks lifecycle and payload fields after comparison. A failed verification leaves a provisional view. [Public request limits](../ARCHITECTURE.md#evidence-and-request-limits)

## Uncoached walkthrough

Give the owner the fixture page and the two IDs. Ask them to identify whether the review has finished, the outgoing and incoming nodes, the subnet size, the rule used, and which conclusions the evidence supports. Ask them to find the members behind a concentration row and return to the overview. Run the task with a held location reply and a completed review. Record their reasoning and navigation. Browser automation verifies interaction behaviour and request receipts. Participant observations require the owner walkthrough.
